# 按步骤点选补录

复用现有 DSH 原生选择卡，按“需求确认 → 技术补录 → 定价口径”分组。同一步的相关缺项用一次 `ask_user_question` 收集，卡片内连续选择、最后整批提交，不按每个字段等待一次模型往返。

## 使用真实控件

需要输入时调用已有工具 `ask_user_question`。模型参数为 `questions:[{id,question,header?,options?:[{label,description?}],multi_select?:boolean}]`；是下划线形式的 `multi_select`。实际返回为 `answers:[{id,selected:[label],custom?}]`。

- 常见项使用 `options`；工序可多选，表面处理等单选。问题及选项使用纯文本，不放图标名、SVG、HTML、Markdown 方框或代码。普通聊天里列出选项不能冒充已显示按钮。
- 数量、用量、单价及准备费不虚构固定选项，省略 `options`，使用原生自定义输入框，提示实际单位；也可粘贴已有计价资料。
- 禁止“自定义数量/自定义牌号/自定义处理/其他”这类没有实际值的占位选项；界面已自带自定义输入。牌号选择提供实际候选值，已知碳钢可列 Q235B、Q355B 并保留原生自定义；不把候选牌号视为已证明的工程替代。
- 原生界面已有自定义和跳过入口，不必增加一个没有具体值的“其他”选项。
- 当前步骤的相关缺项合并为一批，通常不超过六题。用户在卡片内部连续填写，一次提交后才继续模型；已提供的项不重问。
- 调用后等待真实界面返回，不追加重复的文字问题，不用下一条聊天消息代替卡片提交。未返回、关闭或取消时不能声称已保存答案。

字段形状示例（仅为控件定义，不能作为已提交答案）：

```json
[
  {"id":"quantity","header":"数量","question":"请输入本次实际数量（件）"},
  {"id":"surface_treatment","header":"表面处理","question":"本件采用哪种表面处理？","options":[{"label":"不处理"},{"label":"喷粉"},{"label":"镀锌"}],"multi_select":false},
  {"id":"process_route","header":"采用工序","question":"仅勾选本件采用的工序，可多选；此处不确认生产顺序。","options":[{"label":"激光下料"},{"label":"去毛刺"},{"label":"折弯"},{"label":"压铆"},{"label":"焊接"},{"label":"组装"},{"label":"镀锌"},{"label":"喷粉"},{"label":"检验包装"}],"multi_select":true}
]
```

## 需求确认卡

先读取当前任务与实际图纸，保存候选。按缺项选取以下问题，一次请求收集；无需每题往返聊天。

| 信息 | 控件 | 规则 |
|---|---|---|
| 待核对图纸摘要 | 单选“以上信息正确 / 需要修改” | 展示实际读出的名称、材料原文、单位和板厚等必要候选；核对范围仅限本卡可见值 |
| 数量 | 自定义输入 | 已给出时沿用；数量不是文件或页数 |
| 指定牌号 | 单选加自定义 | 只提供与已知材料类别相关的常见候选，不把第一项或推荐顺序当客户要求 |
| 表面处理 | 单选加自定义 | 常见项“不处理、喷粉、镀锌”；不替用户预选 |

“需要修改”不是同意，先收实际修改再采用。用户在最初询价或同一回复中已经给出的需求全部接收，不拆开重问。图纸摘要确认不能连带核对没有展示的精度、密度、完整标题、折弯半径或技术参数；原完整候选保留在历史中。

## 技术补录卡

内部工序、用量和费用由技术人员或传递实际技术资料的操作者填写；姓名未知如实记录，不要求先填姓名。当前缺的采用工序、单件用料、材料单价、准备费和包含项可以放在同一张卡。优先读取已有技术表，只补问实际缺项、歧义或冲突。

- 采用工序用 `multi_select:true`，可提供激光下料、去毛刺、折弯、压铆、焊接、组装、镀锌、喷粉、检验包装等常见候选并允许自定义。说明“仅勾选本件采用的工序”；候选列表不是 AI 已证明需要这些工序。勾选只确认集合，不将选中次序当生产顺序，工艺验证限制保留。
- 用量和费率用自定义输入，保留 kg/件、元/kg、元/件或元/单等实际基础；不默认用量、单价或零准备费。
- 依赖所选工序的单价在真实提交工序后收集：可接受完整计价表，或把尚缺工序的单价放在下一批问题。不要在一批尚未提交的卡片中伪造动态依赖。
- 跳过或“技术暂未给/稍后补”保持缺项。保存其他有效答案后暂停等待，不猜工艺、套旧样例费率或开始报价。

`operation_rates` 是整列表替换。分批收集时合并真实已有费率，保留每次原话或实际选择结果及来源。未与 `process_route` 逐项对应时整组保持待补/待核对，不因第一道有单价就宣布完整；已有值变化时先处理差异，不静默覆盖。生产顺序未验证不影响记录采用工序集合，但不得宣称已验证制造工艺。

## 定价卡

资料 ready 且已有报价要求时接报价 Skill。当前未知的方法、比例和税运口径可放在同一批：方法单选“成本加成 / 目标毛利率”，比例自定义，支持口径单选确认“人民币、未税、不含运费”。已给出条件不重问。

实际选择成本加成才用 `cost_plus`，目标毛利率才用 `gross_margin`；比例从实际输入换算，20% 不是新任务默认值。不支持的币种或税运条件保持待补并说明限制，不将不同意解释为同意。交期、付款和有效期未提供时留待约定，不增加本版必答项。

## 提交结果与来源

1. 将实际问题、选项、问题ID与字段对应关系存为本次上下文；将原生工具实际返回的 `answers` JSON 另存为人工输入来源。它是 UI 实际提交结果，不是模型生成的客户回复。文字消息仍逐字保存。
2. 只按真实 `selected` 与 `custom` 登记。选项列表、第一项、推荐项和草稿不是答案。多选同时包含选中项及自定义内容时两者都保留；补充还是替代不明确时澄清。单选收到多项或选项加自定义等异常时保持待核对。
3. 空 `selected` 且无有效 `custom` 是跳过，不提交覆盖原字段的空事件：缺失仍缺失，待核对候选保持原状态，已有值不清空；不填零、不关闭问题。取消整批不制造答案或修改字段。若“暂不确定/不做”与具体工序同时选中，保持待核对并简短澄清互斥含义。
4. 需求确认或技术补录批次有可保存的有效参数答案时，必须用现有 `apply_customer_reply` / `apply_technical_input` 保存合法输入，保留模拟性质、工程限制和修订。其他题跳过不影响已回答项写入。工序多选加自定义应生成完整采用集合并实际补录，不能仅在回复中说已保存。“需要修改”“暂不确定”只保留真实来源与待办，不作为已核对参数。定价批次按报价 Skill 保存真实答案与独立策略，不走参数补录接口。成功提交卡片不等于业务已保存，以实际写入为准；核对返回结果、字段状态和修订后，才进入下一步或暂停。
5. 本步提交后一次概括保存结果，再显示下一步卡片，不每字段播报一次。历史变更使用新来源和新事件，保留旧快照。

卡片已经收集的值不让用户重新打字确认。只有实际矛盾或修改才追加针对性卡片。工具确实不可用且有明确错误时，说明限制后回退为简短自然语言，不假称已出现按钮。

## 执行与结果

机器步骤自动执行，工具前最多一句业务进度，不逐次讲载荷、命令、版本或编号。用户无需填写 JSON、任务号、来源 ID、事件 ID 或修订号。报价成功显示程序实际单价、数量、总价、税运口径和模拟待审核标识，提供报价及内部明细链接。
