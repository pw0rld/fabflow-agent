# 报价工作台前端

## 当前默认页面（2026-10-22）

`/workbench/` 使用用户提供的 v0 五步模板：上传图纸 → 识别与拆件 → 用料与价格 → BOM 与报价 → 人工审核。源码在项目 `frontend/`，原始导出保存在 `reference/v0-export-20261022.zip`；`deploy/build_frontend.py` 在本地使用 Node / pnpm 检查类型并静态导出到 `web/demo/`。Python 业务服务同源提供导出页面与 `/workbench/api`，服务器不运行 Node，浏览器不依赖外部 CDN 或持有模型密钥。修改源码后需重新构建，不手改 `web/demo/` 产物。

前两步是真实上传与解析：保留原附件，展示真实后台阶段、识别记录、每件参数、原始标注与关联原图。关闭或刷新浏览器不会取消后台任务，查看旧结果不会自动重跑模型；候选仍待人工核对。

后三步全部为明确标识的浏览器模拟。可以沿用真实零件名称 / 图号作为标签，但用料、材料规格、每套用量、工序、价格及金额使用独立演示假设，不按真实解析尺寸核价。修改模拟输入会联动重算；缺项保持未知，不能模拟审核通过；金额按已显示单价乘数量、逐行求和。CSV 带 `DEMO` 标识，模拟审核只改变页面状态，不提交正式参数、报价、BOM 或审批记录，也不对外发送。

旧识别页保留在 `/workbench/legacy/`，仍使用 `index.html`、`app.js`、`recognition.js`、`styles.css` 等原生资源，无需单独构建。历史记录与既有 API 不迁移、不覆盖。完整运行方式见项目根目录 `WORKBENCH.md`。

## 历史完整业务界面说明（兼容保留）

以下是旧业务版本的历史行为说明，不是当前默认模板已实现的真实核价范围。旧主流程为上传资料、确认参数、查看报价；价格管理单独维护版本化草稿。该旧界面调用 `/workbench/api`，所有保存提示、字段状态、金额与预览链接都来自实际服务响应，前端不计算正式成本或报价。当前默认模板的后三步模拟应按上节区分。

- 需求与技术参数按服务返回的字段定义显示；只确认实际显示且提交的字段。空白跳过，不清空已有值。
- 工艺与计价按材料费用、加工费用分组；整单准备费紧邻各工序价格。其他技术信息与价格库查询默认折叠，问题列表可直接跳转、展开并高亮实际输入。
- 常用模板在工艺与计价顶部按需展开，可命名保存多套已经保存、已经核对的工序、费率和费用口径，也可二次确认停用。模板区仅在明确展开或刷新时加载，不增加普通读图或保存请求。
- 模板默认排除数量、板厚、尺寸、图纸观察和单件材料用量；单件材料用量仅在明确勾选后保存。存在未保存的技术输入时，须先保存本批输入再存模板，不能把草稿或隐藏候选收入模板。
- 采用模板先显示当前本单/草稿与模板的对比、适用条件和警示。明确点击“带入本单草稿”后才填入，仍须人工核对保存；取消保持当前草稿，慢速预览返回不会串入另一个任务。自定义费用说明会展开供实际核对。
- 模板未保存的参数保留本单原值，不按零补齐。路线与工序费率必须完整成组，旧的不完整路线模板不可带入，避免隐式沿用本单旧费率；原采用价格库条目失效或不适用时，也只允许预览并说明原因。保存时记录模板版本和实际价格来源，沿用现有费用校验。
- 按单工序费与另收准备费的冲突卡采用本页实际金额和单位，输入变化时立即更新，不重建表单。操作者可定位工序计费方式，或明确选择把本单另收准备费设为 0；该动作只修改草稿并清掉对应的待采用价格引用，保存后才更新记录。不会自动更改工序金额/计费单位，也不声称准备费已包含在其他费用中。
- 费用包含项可选实际适用口径，补充说明按需展开；选项未勾选不自动提交。取消准备费会展开既有包含说明供核对，不静默删除原文或追加未经确认的包含关系。
- 保存只提交明确修改字段、当前实际展示的待核对候选和实际待办要求重新核对的可见字段。已核对且未改动、没有待办的历史值不重复提交；折叠区中未经展示或编辑的新候选不隐式核对。待核对的自定义包含说明默认展开，勾选常见口径时也会展开已有说明，避免隐藏候选随选项一并确认。
- 未提交输入保存在当前浏览器页面的内存中，离开页面会提醒。刷新页面后从服务恢复已保存记录，不把浏览器缓存当业务记录。
- 部分工序金额或单位未填写时，其他有效技术输入仍可保存；该未完整行继续留在表单内，不能变成零费用。
- 服务冲突时保留输入，刷新后展示已保存值与本页输入，操作者核对后再继续。
- 网络结果不确定时保留该次事件 ID 与原始提交，重试相同操作复用该次提交。收到成功后，新的明确操作使用新事件 ID。
- 读图只轮询真实运行状态；状态不确定时继续检查或停止，不能自动启动另一轮。业务是否可核算仍取决于记录校验。
- 读图在服务器后台执行，离开页面不会取消。任务页展示实际阶段、开始时间、已运行时长、最近活动及状态连接，并可展开简单进度记录；没有推测百分比或预计完成时间。列表自动检查运行中的后台任务，结束时在页面提示。
- 后台轮询只更新进度区域或列表行，不重建参数表单。AI 保存了新修订时先提示载入最新参数，本页未提交输入保持原样；加载并核对之后才采用新候选，避免确认未显示的字段。
- 同一字段可展示多处图纸原始标注、来源附件、页码与区域；这些观察记录与正式参数输入分开，不自动换算、不自动填值、不随确认提交。原图链接仅从当前任务已登记附件取得，不使用模型提供的链接。
- 字段区分“本轮未找到”“已识别，单位待确认”“标注待消解”“标注无法辨认”；读图尚未完成时不提前标记未找到。人工已核对字段仍保持其已核对状态，原始标注仅作参考。
- 后台关键字段回查的阶段显示在进度卡内；前端只展示服务返回的状态，不自行启动回查或新一轮读图。观察区随只读轮询局部更新，保持参数输入节点、焦点与光标。
- 价格匹配结果只作候选，先选择、带入表单，再随技术信息人工核对保存。价格修改建立新版本；发布与停用均须实际服务成功。
- 报价与成本文件使用后台给出的同源受控链接，可直接打开或下载。定价方式与比例新任务留空；没有正式审批或自动向客户发送功能。

本地端到端浏览器验收脚本位于 `verification/workbench-browser.cjs`，只允许 `127.0.0.1` 临时服务，明确阻止读图端点及全部外部网络请求。测试资料与 SQLite 均由临时服务根目录隔离，不能指向生产数据运行该脚本。

`verification/workbench-observations-browser.cjs` 使用本地拦截响应模拟多处板厚标注、冲突和回查状态，检查原文不进入确认载荷、来源链接受控与移动端布局；该验收不代表模型已真实读到模拟标注。

`verification/workbench-fee-browser.cjs` 用本地拦截模拟费用冲突、价格引用和待办，验证问题定位、仅草稿变更、按实际确认范围提交、输入保留与 390px 布局，不访问生产或模型。

`verification/workbench-template-browser.cjs` 用本地拦截模拟多模板、保存与停用、预览取消/采用、字段和来源范围、库价失效、旧工序模板不完整以及切换任务时的延迟响应。验收只验证界面和 HTTP 提交契约，不代表模型或生产订单已执行。
