# 开发与部署

这是运行中原型的公开源码起点，尚未完成一键安装或多工厂配置化。服务器专用迁移、代理配置、历史发布脚本和客户案例不在此仓库。

## 运行边界

后端 `src/workbench_server.py` 默认仅监听 `127.0.0.1`。若通过 Nginx 对外提供工作台，必须保护内部管理接口：应用依赖反向代理的认证边界，不可直接将所有 API 作为匿名公共接口转发。`deploy/unified_access_config.py` 保留了现有管理命名空间的配置生成逻辑，使用前需按实例配置并验证。

用户上传和报价服务使用独立订单归属与会话机制；内部核价和原生 CAD 管理仍须位于受保护命名空间。部署者应在服务器验证无会话访问、跨客户访问、内部成本隔离以及打印页权限。

运行数据放在静态目录以外，例如 `/var/lib/fabflow/`；不要将该目录提交到 Git。模型凭据仅由服务端提供，浏览器不得获得 API key、代理节点或内部配置。

## 构建与检查

当前维护约定是仅在远程构建服务器执行 Python 测试、CAD 原生计算、前端编译和浏览器测试，使用独立目录并限制 CPU、内存。无需为首次源码推送在生产实例创建测试订单或消耗模型 token。

可先用合成控制验证公开版空参考适配器及费用结构：

```sh
PYTHONPATH=src:tests .venv/bin/python -m unittest \
  test_public_costing_reference test_batch_cost_sheet test_batch_cost_sheet_http
```

其余测试中仍有历史静态导出和未分发夹具的检查，尚未整理成完整公开 CI；不要把之前私有部署的测试数量当作本仓库完整测试结果。公开样例的来源、许可和用途见 `samples/`。
