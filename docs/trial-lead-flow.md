# 工厂体验与线索流程

本次面向加工厂采购软件：企业资料 → 上传 STEP → 查看拆件、参数及报价草稿 → 申请工厂试用。沿用现有 CAD 服务和订单计算，不因提交线索再次启动模型处理。

## 当前能力

- 官网 `/try/` 默认为三个有明确来源与许可的公共 CAD 样例，不创建客户会话、不恢复客户历史、不扣上传额度、不调用模型。支持原生 3D、候选 BOM 和列明假设的模拟报价。
- 点击“用我的 STEP 体验”进入 `/try/?mode=upload` 后，才挂载原有个人体验；企业名称、加工业务及手机号或微信号必填，联系人称呼选填。原浏览器已保存的私人订单仍仅在该流程中按原归属读取。
- 联系方式是自报资料，固定标记 `unverified`。当前没有短信、微信身份核验、跨浏览器账号恢复或新的账户额度。
- 销售联系意愿单独选择，默认关闭；不选择也可体验，可随时修改。
- 保存资料后才能新上传和提交处理；已有模型与报价仍可查看。全站 10 次额度、每次一个 STEP/STP 的限制沿用原账本。
- 自动保存体验阶段、任务编号和结果条目数；申请试用可关联已有结果，保留独立联系意愿。
- 内部 `/workbench/leads/` 展示脱敏列表、允许联系的详情、体验与申请记录，以及负责人、状态和备注。
- 当前后台复用原 Nginx 内部认证，尚未提供独立销售角色、CRM 推送或导出。体验记录不提供原始 CAD 的公开链接。

## 配置与持久化

`FABFLOW_TRIAL_FLOW_ENABLED=1` 打开该流程；默认 `0` 保留旧体验界面。此开关只表示资料收集流程，不能表示验证完成。

SQLite 位于现有工作目录 `.workbench/trial-leads/leads.sqlite3`，目录权限 `700`、文件 `600`。备份和恢复按私有业务资料处理，不纳入源码或静态发布。

生产后端只监听回环地址。发布时须将 `deploy.trial_leads_access_config.append_leads_access` 生成的 location 加到现有 server 级配置，确保以下页面及 API 继承有效的 `auth_basic_user_file`：

- `/workbench/leads/`，包括静态页面别名；
- `/ortho2cad-test/customer-upload-admin/api/trial-leads` 及其子路径。

代理覆盖审计身份头，不能信任浏览器自报角色。客户资料与申请接口沿用受保护的浏览器 Cookie 和同源提交检查。

资料、申请及后台修改均使用事件编号恢复同一次操作，资料和跟进更新同时检查版本。体验统计存储暂时故障不会覆盖已接受的订单结果，后续查看时可补记；资料必填与订单归属检查仍生效。

## 验收

所有构建、浏览器及后端测试在隔离服务器执行。`test_trial_leads`、`test_trial_leads_http` 使用合成联系人与独立 SQLite；`tools/browser_trial_leads.cjs` 覆盖客户申请、员工跟进、手机布局与认证失败界面，全部业务 API 模拟，不上传客户图纸、不发短信、不调用模型、不扣线上额度。原客户体验脚本另外回归上传恢复、模型预览和报价展示。

部署后另检查真实 Nginx 对内部页面和 API 返回 `401`，公开入口正常载入，客户 Cookie 不能获得内部线索权限，原模型配置、报价规则及额度账本保持。

短信服务后续接入设计见 [官网验证体验方案](verified-trial-leads-plan.md)。
